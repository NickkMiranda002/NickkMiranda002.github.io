In use at MUPAN

Video pipeline in Python: from 2+ days to 5 hours.

MUPAN had a naming convention for its institutional videos, but applying it by hand to a large archive took days. I designed a Python desktop app that reads each video, gathers clues about date, place and content, and proposes a standardized name for a person to approve.

Simulation based on the system's real flow. The data shown is fictional.

.mp4
  1. Date & place
  2. Audio
  3. Frames
  4. AI
  5. Review

          


          

            
Decisions I made

            
    
              
  • Human review was the bottleneck, not the AI. So processing and review run in parallel: while someone checks one name, the next videos are already being analyzed.
    • 
              
  • One provider failing doesn't stop the batch. The app rotates across several API keys when one hits its quota, falls back from Gemini to Claude if one fails, and retries with increasing wait times.
    • 
              
  • AI is one component, not the system. Before calling it, the app pulls the date from three sources (metadata, file and path), turns the video's GPS into a place name and transcribes the audio. The model gets that context ready-made.
    • 
              
  • Care with the originals. Files with accented names are processed from temporary copies, free disk space is checked before starting, and videos already in the standard are skipped.

MUPAN needed a single place to register and find contacts, documents, photos and videos across several departments. I built a web application from scratch with login, departments, forms that adapt to each record type, search across all content and a dashboard with the database's numbers.

          
Records link to each other, files up to 500 MB get image, video and audio previews, and nothing is deleted for good.

          

            
Decisions I made

    •

    • 
              
  • Many-to-many relationships. One contact can appear in several videos and projects, and navigation works both ways.

MUPAN internal tool

        

        

          
Organizing 16,000 files without opening folder by folder.

          
MUPAN's Teams library had around 16,000 files, with the same topic scattered across folders with almost identical names (like "Kadiweu", "kadiweu" and "Kadiweu "). Reviewing it by hand wasn't an option. I built a two-step tool: first it maps and groups, then it applies what a person approved.

          
    
            
  1. Scan the tree
    2. 
            
  2. Group similar names
    3. 
            
  3. Excel for approval
    4. 
            
  4. Apply changes
    5. 
          

          

            
Decisions I made

            
    
              
  • Grouping by edit distance. Folder names are compared ignoring case, accents and extra spaces, so variations of the same topic land in the same group.
    • 
              
  • A person approves, the script executes. The report has one row per group, with the suggested name, the variations and the number of folders and files, so review happens in batch, not file by file.
    • 
              
  • Simulation before running for real. The apply step has a dry-run mode, never overwrites a file and never deletes a folder that still has content. Results come out in Excel, with a summary and a filterable list of actions.

What the alert missed, the script finds.

          
A collection, deduplication and storage pipeline for press mentions.

    2. 
            
  2. Deduplicate
    3. 
            
  3. History in Excel
    4.

The communications team relied on Google Alerts to know who mentioned MUPAN, but it missed a lot: in one example it reported 2 mentions while a manual search found 9. On its first run, the script found around 60.

          

            
Decisions I made

            
    
              
  • Zero cost to start. Free sources only: Google News RSS and DuckDuckGo.
    • 
              
  • History that doesn't get lost. Each run structures the results into a spreadsheet with every field, skips what was already stored and flags what arrived since the last run.
    • 
              
  • Editable search terms. The team adds people's and the organization's names without touching the code.
